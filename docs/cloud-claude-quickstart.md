# Cloud Claude — Quickstart

Stand up a remote Claude Code VPS with Discord control. ~1 hour wall-clock once accounts are ready.

## What you need

### Accounts (free or low-cost)

| Account | Cost | What for |
|---|---|---|
| Hetzner Cloud | ~$40/mo (CCX33) | The VPS itself. Requires payment method + sometimes photo-ID verification (1–24h hold first time). |
| Tailscale | free (up to 100 devices / 3 users) | Mesh VPN. Stable hostnames between laptop / phone / VPS. |
| Discord | free | UI surface. Need an account, server you control, and a developer application for the bot. |
| Anthropic (Claude Code) | per-token usage | Powers the claude sessions. Use your existing Claude/Anthropic login. |

### Local tooling (laptop, macOS via brew)

| Tool | Install | Purpose |
|---|---|---|
| `hcloud` | `brew install hcloud` | Hetzner CLI — provisioning |
| `tailscale` | `brew install --cask tailscale` | Mesh VPN client |
| `mutagen` | `brew install mutagen-io/mutagen/mutagen` | File sync laptop ↔ VPS |
| `bun` | `curl -fsSL https://bun.sh/install \| bash` | Runtime for daemon + session-mcp (also installed on VPS) |
| `git`, `ssh`, `rsync`, `jq` | usually preinstalled / `brew install` | Provisioning + checks |
| SSH key (`~/.ssh/id_ed25519.pub`) | `ssh-keygen -t ed25519` if missing | Auth into VPS |

### Tokens / IDs you'll generate

| Token / ID | Source | Used for |
|---|---|---|
| Hetzner API token | Hetzner Cloud Console → Project → Security → API tokens → Generate (Read+Write) | `hcloud context create claude` |
| Tailscale auth key | <https://login.tailscale.com/admin/settings/keys> → Generate (Reusable=off, Ephemeral=off, 90d) | `TAILSCALE_AUTHKEY=tskey-auth-...` |
| Discord bot token | <https://discord.com/developers/applications> → New App → Bot → Reset Token | `DISCORD_BOT_TOKEN` in daemon `.env` |
| Discord channel ID | Discord → Developer Mode → right-click channel → Copy Channel ID | `DISCORD_SESSIONS_CHANNEL_ID` in daemon `.env` |
| Daemon shared secret | `openssl rand -hex 32` (auto-generated by `install-vps.sh`) | `DAEMON_TOKEN` |
| Your Discord user ID | Discord → Developer Mode → right-click your name → Copy User ID | seed `access.json` allowlist |

Save all of these in a password manager before starting.

### Discord prep checklist

1. Create a Discord application + bot in the developer portal.
2. **Enable "Message Content Intent"** under Privileged Gateway Intents — required for DM content.
3. OAuth2 URL Generator → scopes `bot`, permissions: Send Messages, Read Message History, Manage Threads, Create Public Threads, Add Reactions, Attach Files, Embed Links.
4. Open the generated URL, invite the bot to a server you own.
5. Create (or pick) a **text channel** in the server for session threads.
6. If the channel is **private**, explicitly add the bot under Channel Settings → Permissions → Add Member.
7. Enable Developer Mode in Discord client and copy: bot User ID, channel ID, your User ID.

## Bootstrap (one-time, ~1 hour)

Run on the laptop unless noted.

### 1. Authenticate hcloud

```bash
hcloud context create claude         # paste Hetzner API token
hcloud server-type describe ccx33    # confirm token works
```

### 2. Provision the VPS

```bash
TAILSCALE_AUTHKEY=tskey-auth-XXXXX \
SERVER_LOCATION=ash \
./discord-daemon/scripts/provision-hetzner.sh
# ~60s later: server up at <public-ip>, auto-joined to tailnet
```

Wait until cloud-init finishes:

```bash
ssh bryan@claude-vps 'sudo cloud-init status --wait'
```

### 3. Copy daemon code to VPS

```bash
ssh bryan@claude-vps 'mkdir -p ~/dev'
rsync -av --exclude=node_modules --exclude=.giantmem \
  ./discord-daemon ./session-mcp \
  bryan@claude-vps:~/dev/claude-code-config/
```

### 4. Run installer + write `.env`

```bash
ssh bryan@claude-vps 'sudo bash ~/dev/claude-code-config/discord-daemon/scripts/install-vps.sh'
# fails at git clone — expected. The relevant steps complete.
```

Then edit `.env`:

```bash
ssh bryan@claude-vps 'vim ~/.claude/channels/discord/.env'
```

```
DISCORD_BOT_TOKEN=MTxxx...
DISCORD_SESSIONS_CHANNEL_ID=12345...
DAEMON_TOKEN=<keep auto-generated>
DAEMON_BIND_HOST=0.0.0.0
DAEMON_BIND_PORT=7777
```

> **Critical:** `DAEMON_BIND_HOST` must be `0.0.0.0`, not the tailnet IP. Otherwise same-host claude sessions can't reach the daemon over loopback.

### 5. Allowlist your Discord user

```bash
ssh bryan@claude-vps 'cat > ~/.claude/channels/discord/access.json <<EOF
{
  "dmPolicy": "allowlist",
  "allowFrom": ["<your-discord-user-id>"],
  "groups": {},
  "pending": {}
}
EOF
chmod 600 ~/.claude/channels/discord/access.json'
```

### 6. Start the daemon

```bash
ssh bryan@claude-vps 'sudo systemctl enable --now discord-daemon && sleep 2 && sudo journalctl -u discord-daemon -n 10 --no-pager'
# Look for: "daemon: gateway connected as <bot>#XXXX"
```

Sanity check from laptop:

```bash
TOKEN=$(ssh bryan@claude-vps "grep DAEMON_TOKEN ~/.claude/channels/discord/.env | cut -d= -f2")
curl -H "x-daemon-token: $TOKEN" http://claude-vps:7777/health
# {"ok":true,"sessions":0}
```

### 7. Install Claude Code on the VPS

```bash
ssh bryan@claude-vps '
  curl -fsSL https://claude.ai/install.sh | bash
  echo "export PATH=\"\$HOME/.local/bin:\$PATH\"" >> ~/.bashrc
'
```

Log in to claude on the VPS (interactive, one-time):

```bash
ssh bryan@claude-vps
cd ~/dev/test 2>/dev/null || mkdir -p ~/dev/test && cd ~/dev/test
~/.local/bin/claude
# follow the /login URL in your laptop browser
# Ctrl-D to exit after successful auth
```

### 8. Register the session-mcp as discord MCP

```bash
ssh bryan@claude-vps '
  TOKEN=$(grep DAEMON_TOKEN ~/.claude/channels/discord/.env | cut -d= -f2)
  PATH=$HOME/.local/bin:$PATH claude mcp add discord /home/bryan/.bun/bin/bun \
    --scope user \
    -e DISCORD_DAEMON_URL=http://127.0.0.1:7777 \
    -e DISCORD_DAEMON_TOKEN="$TOKEN" \
    -- run /home/bryan/dev/claude-code-config/session-mcp/src/server.ts
'
```

### 9. (Optional) Mutagen file sync

```bash
./scripts/mutagen-sync-dev.sh "$(hcloud server ip claude-vps)"
mutagen sync list dev          # confirm "Watching for changes" eventually
```

### 10. (Optional) Personal claude config on VPS

If you want your stowed `~/.claude` setup mirrored to VPS:

```bash
ssh bryan@claude-vps '
  mkdir -p ~/.claude
  cd ~/dev && stow --restow -t ~/.claude claude-code-config
  # bridge laptop-absolute paths in stowed configs
  sudo mkdir -p /Users && sudo ln -sfn /home/bryan /Users/bryan
  mkdir -p ~/.nvm/versions/node/v24.11.1/bin
  ln -sfn /usr/bin/node ~/.nvm/versions/node/v24.11.1/bin/node
'
```

## Day-to-day use

```bash
# laptop
ssh bryan@claude-vps
tmux new -A -s main           # attach or create named tmux on VPS
cd ~/dev/<some-project>
claude --dangerously-load-development-channels server:discord
# → Discord thread "<project>-XXXX" spawns automatically
```

`Ctrl-b d` to detach the tmux session — claude keeps running on the VPS.
Reopen later with the same `ssh + tmux attach`.

Phone workflow: open Discord, find the thread, post a message — the VPS claude session replies in the same thread. DM the bot for control commands (`list`, `kill <label>`, `status <label>`).

## Troubleshooting cheat-sheet

| Symptom | Likely fix |
|---|---|
| `--channels` rejects `server:foo` | Add `--dangerously-load-development-channels server:foo`; can't be used with `--channels` |
| `no MCP server configured with that name` | `claude mcp add ...` — settings.json `mcpServers` blocks aren't auto-loaded |
| `download_attachment failed: channel not allowlisted` (bundled plugin) | Old `discord@claude-plugins-official 0.0.4` bug — apply `scripts/patches/discord-dm-recipient.patch` via `scripts/apply-discord-patch.sh`, then restart MCP |
| Mutagen agent install fails with `Permission denied` | Use VPS **public IP**, not tailnet hostname — Tailscale SSH strips exec bits |
| Sync stuck "Reconciling changes" with hundreds of conflicts | Plugin runtime caches diverged. Recreate with the `mutagen-sync-dev.sh` wrapper (its ignore list covers them) |
| Hook errors `/Users/bryan/.nvm/.../node: not found` on VPS | Create `/Users/bryan → /home/bryan` symlink + bridge node path (step 10 above) |
| Daemon's bot shows offline after restart | systemd restarted — `journalctl -u discord-daemon -n 20` to confirm reconnect; gateway usually back in <5s |
| Session-mcp logs `Unable to connect` to daemon | `DAEMON_BIND_HOST=0.0.0.0` not set, or wrong; daemon isn't listening on loopback |

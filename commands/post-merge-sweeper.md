Pick up the review threads that slipped through when **this worktree's MR** merged.

## Worktree scoping model

One session/loop handles exactly one source MR — the one merged from this worktree's branch. Run separate `/loop /post-merge-sweeper` instances in each worktree.

## Preconditions

- `glab auth status` ok
- In a git repo with a GitLab remote
- `git status --porcelain` clean — if dirty, **abort with a one-line note**. Do not stash.
- Current branch is **not** `main` / `master` / `stage`. (If you're sitting on default branch in this worktree, there's no source MR to sweep; exit clean.)

## Steps

1. **Resolve current branch and recently-merged MR for it**:
   ```
   BRANCH="$(git branch --show-current)"
   glab mr list --source-branch="$BRANCH" --state=merged --output=json --per-page=5
   ```
   - Zero results → exit clean: `no merged MR from branch <BRANCH>`
   - Filter to MRs with `merged_at > now - 48h`. Pick most recent.
   - Older than 48h → exit clean (stale window).
   - Capture `iid`, `project_id`, `target_branch` (e.g., `main`), reviewer list.

2. **Fetch all discussions** on the merged MR (resolved + unresolved):
   ```
   glab api "projects/<project_id>/merge_requests/<iid>/discussions" --paginate
   ```
   Filter for:
   - `resolved == false`
   - `system == false`
   - last note timestamp `< merged_at` (the comment existed at merge — wasn't added later)
   - last note author != yourself

3. **Classify** identical to `babysit` — only act on `actionable_simple`. Defer the rest by replying on thread and skipping.

4. **Nothing actionable** → exit clean.

5. **Check follow-up branch doesn't already exist**:
   ```
   SWEEP_BRANCH="followup/${BRANCH}-sweep-$(date +%Y%m%d)"
   git ls-remote --exit-code --heads origin "$SWEEP_BRANCH" && exit 0   # already swept
   ```

6. **Build follow-up MR**:
   1. Sync default: `git fetch origin && git checkout <target_branch> && git pull --ff-only`
   2. New branch: `git checkout -b "$SWEEP_BRANCH"`
   3. Make all the fixes. Run `py-check` / `ts-check`.
   4. Caveman commit: `review: address post-merge nits from !<iid>`
   5. Push: `git push -u origin "$SWEEP_BRANCH"`
   6. Open MR (delegate to `kai:open-mr` if available, otherwise `glab mr create`):
      - Title: `review: post-merge sweep for !<iid>`
      - Description:
        ```
        Follow-up to !<iid>.

        Addresses review threads that were left unresolved when the MR merged:

        - <thread-url-1> — <one-line summary of what was changed>
        - <thread-url-2> — <one-line summary>

        Generated by /post-merge-sweeper
        ```
      - Base branch: `<target_branch>` from step 1
      - Assign self, add reviewers from original MR
   7. On each original thread, reply `addressed in follow-up !<new-iid>` and resolve the thread.

7. **Return** to the original worktree branch:
   ```
   git checkout "$BRANCH"
   ```
   Even if the branch is technically dead post-merge, the worktree expects to stay on it until the user cleans up.

## Safety rails

- **One follow-up MR per run** — this command handles exactly one source MR (this worktree's).
- **Never delete branches.**
- **Skip if sweep branch already exists** on the remote.
- **Never sweep MRs older than 48h** — the context is dead.
- **Skip if MR author != @me** (paranoia in case the branch was reused).

## Output

```
swept !1234 → !1240 (3 nits)
```

or
```
nothing to sweep — !1234 merged clean
```

or
```
skipped — already swept (followup/feat-y-sweep-20260523 exists)
```

## Failure modes — exit clean

Network/auth/conflict → log + exit 0. Never crash the loop.

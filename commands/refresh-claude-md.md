Refresh the project's CLAUDE.md with current codebase state, like a targeted re-init.

## Worktree Detection

Determine if we're in a git worktree:

```bash
git_common=$(git rev-parse --git-common-dir 2>/dev/null)
git_dir=$(git rev-parse --git-dir 2>/dev/null)
```

If `git_common` and `git_dir` differ, we're in a worktree. The worktree base is the parent directory of `git_common` (the directory containing `.bare/`). Look for `wt-bootstrap/CLAUDE.md` or `bootstrap/CLAUDE.md` there.

Report the detection result before proceeding:
- "Detected worktree. Will update both CLAUDE.md and {base}/wt-bootstrap/CLAUDE.md"
- "Not a worktree. Will update CLAUDE.md only."

## Find Existing CLAUDE.md

Check in order: `./CLAUDE.md`, then `./.claude/CLAUDE.md`. If neither exists, treat this as a fresh init and create `./CLAUDE.md`.

## Scan the Project

Read actual files to gather current state. Check each of these if they exist:

1. **Build/run commands**: `Makefile`, `package.json` (scripts section), `Taskfile.yml`, `justfile`, `Cargo.toml`, `pyproject.toml`, `Rakefile`, `Dockerfile`, `docker-compose*.yml`
2. **Source structure**: list top-level directories, identify primary language from file extensions, find the main source directories
3. **Config and env**: `.env.example`, `docker-compose*.yml` (environment sections), config files that define env vars
4. **CI/CD**: `.gitlab-ci.yml`, `.github/workflows/`, `Jenkinsfile`
5. **Dependencies**: `requirements.txt`, `go.mod`, `package.json`, `Cargo.toml`, `Gemfile`, `pyproject.toml`
6. **Tests**: locate test directories, identify test framework from config or imports
7. **Deployment**: Helm charts, Kubernetes manifests, Terraform, deploy scripts

Do NOT read every source file. Read key entry points and module indexes to understand architecture, not the full codebase.

## Update Strategy

Read the existing CLAUDE.md. Categorize each section:

**Auto-refresh these** (derived from files, always regenerate):
- Commands / build / test / run instructions
- Module/file structure listings
- Environment variables table
- Docker Compose services
- Dependency lists
- Deployment info
- Endpoints list

**Preserve these** (contain human judgment, keep as-is unless clearly outdated):
- "What This Is" / project description (refresh only if significantly wrong)
- "Key Design Decisions" or similar
- Architecture prose (request flow diagrams, design rationale)
- Coding conventions, patterns, gotchas
- Any section with opinionated guidance

**Merge approach**: for sections that exist in the current CLAUDE.md, update the factual content while preserving the prose and structure. For sections that are missing but should exist based on what was found in the scan, add them. Do NOT remove sections that exist even if you can't verify them from code -- the human put them there for a reason.

## Write Results

1. Write the updated CLAUDE.md to its current location
2. If in a worktree and `wt-bootstrap/CLAUDE.md` exists, write the same content there
3. Show a brief summary of what changed (sections added, sections refreshed, sections preserved)

## Output Rules

- Match the existing CLAUDE.md style (heading levels, formatting conventions)
- If the existing file uses tables, keep using tables
- If it uses fenced code blocks for commands, keep that format
- Keep the file concise -- CLAUDE.md is read every session, bloat costs tokens
- No emojis
- No "generated by" footers or timestamps
